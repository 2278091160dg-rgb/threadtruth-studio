# 状态门禁 + 交互分支 + 前台文案(core,风格无关)

> 抽取自基线 `flow-gates.md`;基线输入/授权/安全门禁继续保留,并叠加多风格路由、look-1 身份锚点与商业 QA 状态阻断;具体风格由所选 pack 决定。

## 1. 资产分类(8 类)

| AssetKind | 含义 | 能否作服饰事实源 |
|---|---|---|
| `GARMENT_IMAGE` | 真实清晰服饰图(单件/完整outfit/平铺/真人穿搭/正背面/细节/面料/多色SKU) | ✅ 是 |
| `CONFIG_FILE` | MD / 配置文件 / 系统文档(含本 skill 源文档、风格包 YAML) | ❌ 否 |
| `PRD_FILE` | 需求文档 | ❌ 否 |
| `PROMPT_FILE` | 提示词文件 | ❌ 否 |
| `SCREENSHOT_OR_UI` | UI/网页/聊天/设计稿截图 | ❌ 否 |
| `NON_GARMENT_PRODUCT` | 食品/狗粮/家电/美妆/3C/家具/包装盒/宠物用品 | ❌ 否 |
| `UNCLEAR_IMAGE` | 服饰严重模糊、无法判断品类/颜色/版型 | ⚠️ 需补图 |
| `UNKNOWN` | 无法归类 | ❌ 否 |

## 2. 状态门禁表(硬规则)

| 当前状态 | 能否进入"生图" | 规则 |
|---|---|---|
| 收到 `CONFIG_FILE`/`PRD_FILE`/`PROMPT_FILE` | ❌ 绝不 | 配置文件永不能进入生成 |
| 收到 `SCREENSHOT_OR_UI` | ❌ 绝不 | 截图不是服饰源 |
| 收到 `NON_GARMENT_PRODUCT` | ❌ 绝不 | 引导切电商系统 |
| 收到 `UNCLEAR_IMAGE` | ❌ 暂不 | 先请用户补正面/背面/细节图 |
| 收到 `GARMENT_IMAGE`,识别未完成 | ❌ 暂不 | 必须先完成识别 |
| 识别完成,用户未表达生成意图 | ❌ 暂不 | 只出识别卡 + 主推/备选 + 当前完整 24 包选择目录 + 模式选择;识别卡可显示输出形态/交付规格默认值,但不进入生图 |
| **最长匹配后仍命中 ≥2 个不同显式风格包,或单一显式 pack 与已识别性别/品类事实或 `anti_categories` 存在边界张力(style-router §2)** | ❌ 暂不 | 状态 `style-conflict-hold`:多 pack 列候选并确认主次;单 pack 张力则请用户选“保留原事实、只借氛围”或“改走更适配路线”;确认前不选定/不生图(`fallback_used=conflict`) |
| 当前 host/session 无任何原生图片生成能力 | ❌ 绝不 | 状态 `tool-blocked`;不走 API/CLI/network fallback;只出提示词或迁移到支持原生生图的环境。Codex Desktop/ChatGPT 生图环境不要求工具名逐字叫 `image_gen` |
| 识别完成 + 动作0(预览) | ✅ 出 1 张六宫格预览 | 进 image_gen 1 次,状态 `preview-grid`,非成片。**例外:用户把六宫格当『成品/最终/交付』→ 不生图,走 GRID-FINAL / 分支 4d** |
| 识别完成 + 动作1/2(成片/测试) | ✅ 可生成独立成片 | 进 image_gen;**未选模式时用 A 自动推荐**(B9)选 B/C/D 之一 |
| `preview-grid` + 用户确认方向 | ✅ 进成片 | 逐张闭集生 6 张独立图(串行+计数) |
| 动作=3(只出提示词) | ❌ 不生图 | 只走提示词输出,禁调 image_gen;未选风格时必须标注"主推=AI 推荐非用户确认"或先请用户选风格代号 |
| `image-draft` + 任一 `qa-retry` | ❌ 不可发布 | 只报告失败编号/原因;等待用户明确授权对应单张重试,不得自动烧第 7 次调用或升 `image-ready` |
| `image-draft` + 仅 `qa-pass`/`qa-user-review` | ⚠️ 待用户确认 | 用户须对照实物/高清源图确认硬事实并关闭待核项,同时知悉 AI 标识义务;否则仍不是 `image-ready` |

补充:模式/风格选择不能绕过输入门禁;"直接生成"不能绕过服饰识别。**B9:任一生图动作若用户没指定 B/C/D,默认走 A 自动推荐在 B/C/D 中选一个,绝不无模式直接生成。**

**B9-STYLE(硬门禁,与 B9 同强度;STEP13 A-4a/A-5):** 用户**未给显式风格代号**就说"直接生成/生成6张/直接生成6张"时,**必须先停在 `recognition-ready` 出 style-router 推荐(主+2备选)+完整 24 包选择目录等用户确认**;**绝不自动默认、绝不回落到任一风格(尤其禁回落 legacy 韩系 `korean-fashion-editorial`)直接进生成烧额度**。用户只要提示词(动作3)时也不能静默替用户定风格:若未选定注册风格代号,输出提示词前必须显式写明"以下提示词基于 AI 主推风格=<X>,这是推荐非用户确认;你也可从下列完整 24 包中改选",并展示目录;或先输出主推+2备选+完整目录,请用户选代号后再展开。模式可由 A 自动在 B/C/D 选一(B9),但**风格不可被系统替用户定**——风格确认是付费层前的强制 transition,提示词层也必须保留"推荐非确认"标识。
- **"显式风格代号" = style-router 注册表里的代号**(如 `韩系/法式/电商/old money`…)。**非注册表的模糊风格词一律视为"未确认"**(DeepSeek 复审堵点):"好看/自然/高级/默认/系统推荐/标准/你们常用的/随便/无所谓/不限",以及只否定不正选("不要韩系也不要日系")——这些都**不构成已选风格**,仍走 B9-STYLE 停确认,**不得据此回落任一具体风格**。
- 元指令豁免无效:用户说"我确认过了/不用再问/赶时间"但本次仍无有效注册代号 → **照样停确认**,确认风格是付费层前不可绕过节点。

**GRID-FINAL(硬门禁;STEP13 A-8):** 用户把『六宫格/九宫格/grid/拼图/拼贴/contact sheet』与『最终成品/成片/交付/final/就这一张』**耦合**(如"生成一张6宫格当最终成品")→ **不是合法动作0**,走分支 4d **硬拒绝、不调 image_gen**。动作0 六宫格预览仅当用户要"看方向/先看预览"**且未把它当成品**时才触发。
- **不分动词**(DeepSeek 复审堵点):生成/做成/合成/输出/拼成/导出/拼/弄成 layout… **任何动词**,只要"六宫格类布局 ∧ 终态交付意图"在同一语义窗口共现即触发硬拒绝,不因"看似只是格式转换"放行。
- **跨轮不复用为成片**:若会话已出过 `preview-grid`,用户随后说"就用这个/拼成一张当终版" → 不是新格式操作,按 `prompt-build.md §4.3` 预览→成片红线**重新征求 6 张独立成片授权**,绝不把预览图当成品交付。

## 3. 六条交互分支

### 分支 1:只上传配置文件 / MD / PRD / 提示词文件
状态 `gate-blocked`。**必须逐字输出以下回复(含完整 A/B/C/D 四模式菜单,不得省略模式行)**:
```
已收到系统配置文件。它不是服饰事实源。
请继续上传一张真实、清晰的服饰图片,我会先识别服饰,再让你选择风格与生成方式:
A. 自动推荐  B. 棚拍版(最保真,适合新品测试)  C. 场景版(更像时尚大片)  D. 混合版(前棚拍后场景)
当前不会生图。
```

### 分支 2:上传 UI/页面/聊天截图
状态 `gate-blocked`。回复:
```
我识别到你上传的是截图 / UI / 页面资料,不是可作事实源的真实服饰图片。
我可以帮你分析截图里的流程或配置,但不会把它当服饰图生图。请上传一张真实、清晰的服饰图片。
```

### 分支 3:上传非服饰商品
状态 `gate-blocked`。回复:
```
该系统是服饰人像多风格生成系统,不适合直接用于非服饰商品图。
当前图片更像食品 / 家电 / 美妆 / 3C / 家具 / 包装盒等非服饰商品。
请切换到电商商品图系统,或上传真实服饰图片。
```

### 分支 4:上传真实服饰图,但未说生成
状态 `recognition-ready`。输出顺序:
1. 服饰识别卡片(见 `recognition.md`,含性别年龄轴/品类轴/用途线索)
1b. **输出形态 + 交付规格线索 + 目标画布:**展示默认输出形态(通常为真人模特)、用途构图线索与按 `modes-scenes.md §4` 解析出的精确目标比例;只用一句 opt-in 提示:"默认真人模特人像;如需平铺/挂拍/人台/不露脸,或覆盖电商主图/小红书/详情页的比例与留白,可直接写在风格动作里。"不得扩成多选问卷,不得放到首个门禁句里。用户未给用途/比例时沿用动作1默认 `2:3`,不新增强制追问。
2'. **AI 风格推荐(调 `style-router.md`:输出主推 + 2 备选 + 理由 + route-trace;免费文字层,不生图)。最长匹配后仍命中多个不同显式风格包,或单一显式 pack 与已识别性别/品类事实存在边界张力 → 走 `style-conflict-hold`(分支 4c)。不得因视觉可融合而静默合包,也不得静默改服饰事实或模特性别。**
2a. **完整风格选择面板(风格未确认时必显):**紧跟推荐区输出标题 `全部可选风格(24)`;以 `style-router.md §6` 注册表和当前已加载 pack 为唯一数据源,把 24 个 pack **每个恰好展示一次**,格式为 `中文短名 (slug)`,可按 `style-router.md §6.1` 分 4 行/组紧凑显示。标出 `AI主推`/`备选`,并逐字表达等价语义:`推荐只是建议,不是替你决定;你可以从全部24个风格中自由选择一个主风格。`目录不附 24 段长说明,不把页面做成问卷。明确告知`选风格 ≠ 生图授权`。
   - 用户已在本轮给出单一有效注册风格时,不重复铺满 24 项、不追加选择阻断;确认当前风格并用一句 `仍可从24个风格中改选` 保留改选权即可。
   - 童装/儿童路线在目录后追加:`24个风格均只作为视觉方向候选;实际执行必须经过儿童安全转译,R1优先,不采用成人化、性感化、暴露或危险元素。`用户仍可选主风格,但选择不能放宽 R1;命中 `anti_categories`/品类张力时走 `style-conflict-hold`,童装敏感品类仍按安全规则推荐平铺/挂拍/人台并说明原因。
2. 推荐模式 + 推荐理由
3. 模式选择(A/B/C/D)
4. 下一步动作(**0 先出六宫格预览看方向** / 1 直接生成6张独立成片 / 2 先生成1张测试 / 3 只输出6条提示词)
5. 提示可回复 `法式 A1`/`电商 B0`/`韩系 C2`/`D3`;**推荐两段式 `<风格> B0 → 确认 → 全部生成`**
**禁止在用户确认风格代号 + 生成动作前生图。** 已经明确 `风格代号 + 模式 + 动作`(如 `法式 B0`/`电商 B1`)时,不要因为输出形态或交付规格未指定而新增强制追问;沿用默认真人模特与对应用途默认规格,除非风险规则必须降级或用户主动指定平铺/挂拍/人台/不露脸/细节。

### 分支 4b:动作 0 — 六宫格方向预览
触发:用户回复含 0 的快捷键或说"先出预览/先看方向/六宫格看看"。**前置守卫:若用户把六宫格/grid 当『成品/最终/交付/就这一张』(GRID-FINAL),不属本分支,走分支 4d 硬拒绝、不调 image_gen。**
1. 校验已过输入门禁 + 已识别 + **已选定风格代号**(未选先走 2′ 推荐)。
2. 校验当前会话有可调用原生图片生成能力(Codex Desktop/ChatGPT 内置生图也算);若确认没有,走分支 5c `tool-blocked`。
3. 用户没指定模式 → 走 A 自动推荐选 B/C/D 之一(B9)。
4. 调 **1 次** image_gen 出 1 张六宫格(拼装见 `prompt-build.md §4.2`,底座来自所选 pack),**必带小号低干扰"方向预览·非成片"单行标记**。
5. 产出状态 `preview-grid`。回复明确:"这是低分辨率方向预览,不是成片。方向满意请回复『全部生成/动作1』,我再逐张生成 6 张高清独立图;或说『第N格调整』改方向(最多 3 轮)。"
6. **绝不**把这张当成片,**绝不**标 `image-draft`/`image-ready`。

### 分支 4c:显式风格冲突或风格×事实边界张力
触发任一条件:

1. 按 style-router §2 第0步完成规范化、同包别名折叠和最长完整词淘汰后,仍命中 ≥2 个不同 slug。互斥风格与视觉可融合风格都走本分支,不得静默合成一个 pack。
2. 只命中 1 个显式 pack,但它与已识别性别/品类事实存在明显边界张力,或品类命中该 pack `anti_categories`(例:女装连衣裙 + cityboy)。

状态 `style-conflict-hold`。多 pack 回复列出候选:互斥时简述取向并请二选一,可融合时请用户确认单一主风格或明确融合主次。单 pack 张力则说明冲突,请用户选 `保留原服饰/性别事实,只借该风格氛围` 或 `改走更适配路线`;同时说明用户也可从完整 24 包目录改选另一个单一主风格。`fallback_used=conflict`;**确认前不选定、不生图**。用户确认后回分支 4。

### 分支 4d:六宫格被当成『成品/最终』(GRID-FINAL 硬拒绝;STEP13 A-8)
触发:用户把『六宫格/九宫格/grid/拼图/拼贴/contact sheet』与『最终成品/成片/交付/final/就这一张』耦合(如"生成一张6宫格当最终成品""六宫格直接当成片")。
**风格前置锁:** 本分支固定二选一仅在用户已提供注册风格代号或本轮已确认风格后生效。未确认风格时,即使用户要求"6宫格成品/直接生成6张",也不得用 4d 选项承接生成意图;必须先回退到 B9-STYLE 风格门禁,输出主推+2备选+完整 24 包目录并等待用户自由确认。
**绝不调 image_gen**(一次都不烧)。固定回复:
```
六宫格只能作"非成片方向预览",不能当最终成品——它是低分辨率拼图,无法逐张做服饰保真审计。
要拿到可用成品,标准是逐张生成 6 张高清独立图(消耗订阅额度)。请二选一:
(a) 先出 1 张"非成片"方向预览看排布(动作0);
(b) 直接逐张生成 6 张独立成片(动作1)。
```
**到此停住等用户明确二选一**;未选定前不调 image_gen,不自动降级为动作0 偷偷生预览。状态保持 `recognition-ready`(若尚未选风格,同时受 B9-STYLE 约束)。若需要提醒可换风格,只能在固定二选一之后附一句"也可以先回复风格代号再选择动作",**不得把换风格并列成第三个主选项**,不得自行扩展固定回复。

### 分支 5:进入成片(用户明确说生成,如"直接生成6张"或预览确认后)
**0. 风格门禁(B9-STYLE 硬前置):** 若用户**未选定显式风格代号**(仅说"直接生成/生成6张"),**不进本分支**——回退分支 4 出 `recognition-ready` + style-router 推荐等用户确认风格;**绝不自动默认/回落任一风格(尤其 legacy 韩系)直接生成**。模式未指定可走 A 自动推荐(B9),但风格必须用户确认。
依次内部完成:识别服饰 → 判断输入类型 → 判断风险等级 → **确认已选定风格 pack** → 读取输出形态/交付规格(默认真人模特;用户可 opt-in 平铺/挂拍/人台/不露脸/细节;高风险按 safety 降级并明示) → **按 `modes-scenes.md §4` 锁定本组 `canvas_contract`** → 校验当前会话有可调用原生图片生成能力(确认无则走分支 5c) → 自动推荐模式(用户没指定时用推荐模式,B9)→ 批量额度提醒确认 → **闭集串行**生成独立图。真人/不露脸先只生 look-1,按 `prompt-build.md §4.0a` 验收后才将其作为 identity-only anchor 与上传服饰源一起传给 look-2…look-6;平铺/挂拍/人台跳过身份锚点。前一张落盘后先按 `prompt-build.md §4.0b` 读取元数据,通过目标比例/批次像素门禁再发下一张,**严禁并行/多套并行** → 每张按 `commercial-qa.md` QA → 完成后核对应有6/实际数/失败编号/调用数。产出 `image-draft`。
- look-1 未通过服饰硬事实、人体/安全或身份种子 QA:立即停止余下 5 张,不传播失败锚点;报告 `qa-retry` 并等待用户明确授权“重试 look-1 后继续余下 5 张”。
- look-2…look-6 一般服饰/构图 QA 失败:可完成当前已授权闭集内其余编号,但失败图保持 `qa-retry`;未经用户明确单张重试授权不自动重试。**比例或批次像素失配是系统性画布故障,须立即停止后续未调用编号**,报告目标/实际元数据并等待授权,避免继续烧额度。任何补图/重试都不得让单次请求超过 6 次 image_gen 调用。
- 用户提到商用/上线/客户交付/电商主图/商品详情/投放/品牌大片时,必须输出 `commercial-qa.md` 的逐张+整组报告。所有 `qa-retry` 关闭且用户确认硬事实/待核项/AI 标识义务后,方可升 `image-ready`。
- 若来自 `preview-grid` 确认:继承预览阶段的风格/模式/服饰事实/输出形态/交付规格/对应闭集编号(真人=姿势母版;非人像=`prompt-build.md §1a` 构图 #N),不重新随意发挥。
- 落盘失败按 `prompt-build.md §4.4` B3 报缓存路径,不重试制造并发。

### 分支 5c:当前会话无原生图片生成能力
状态 `tool-blocked`。触发:用户要求预览/测试/成片,但当前 host/session 经确认没有任何可调用原生图片生成能力。**不要只凭"没看到字面量 image_gen"、shell 工具列表、截图文字或环境变量判断;Codex Desktop/ChatGPT 图片生成环境可继续用原生生图入口。**
必须回复:
```
当前会话没有可调用的原生图片生成能力,所以我不能在这里生图。
本 skill 不使用 OPENAI_API_KEY / OpenAI API / CLI fallback / 联网脚本替代原生生图。
我可以继续给你:1) 服饰识别卡片;2) 6 条可复制到支持原生图片生成的 Codex/ChatGPT 环境里的提示词。
请在支持原生图片生成的 Codex/ChatGPT 图片生成环境中继续,或回复"只要提示词"。
```
禁止动作:检查或读取环境变量、使用 `OPENAI_API_KEY`、请求用户开启 network 来跑 API、执行 `openai`/`curl`/自写脚本、编造已生成图片路径。

### 分支 5b:动作 3 — 只输出 6 条提示词
触发:用户回复含 3 的快捷键或说"只要提示词"。状态 `prompts-only`。输出:6 条编号提示词(真人模特=姿势母版+头部视线;不露脸=姿势母版+脸部/视线替换;平铺/挂拍/人台=非人像构图 #1-#6 + 转译后的模式场景/陈列环境;均叠加所选/推荐风格底座+服饰保真句式)+ 通用负面词。**全程不调 image_gen。** 不出图、不出六宫格。

**未选风格时的硬子规则(STEP13 A-5):**
- 若用户没有给注册风格代号,但要求"先别生图/只要提示词/给我6条提示词",允许停在提示词层,但必须二选一处置:
  1. 直接输出 6 条提示词时,开头必须写明:这些提示词基于 **AI 主推风格=<X>**,这是推荐方向,**不是用户已确认的风格代号**;同时展示完整 24 包目录并说明可自由改选,如回复 `法式 A3` / `韩系 A3` / `电商 B3` 等代号改写。
  2. 或先输出 style-router 主推+2备选+理由+完整 24 包选择目录,请用户自由选风格代号后再展开 6 条提示词。
- 严禁静默采用单一风格且不标注"推荐非确认";严禁默认 legacy 韩系;严禁把"clean/quiet luxury/高级/自然"等模糊风格词当作用户确认。

### 分支 6:重试单张(如"重试第3张""第5张不好")
只重试指定单张,继承上传服饰事实源、原档案、所选 pack、原 `canvas_contract`/`batch_canvas_baseline` 与适用的已验收 look-1 identity-only anchor,只修复指定问题。**不重做整组,不把 QA 发现自动等同付费重试授权。** 继承项与 retry patch 模板见 `prompt-build.md §7`;重试后重新执行逐张+整组商业 QA 与元数据门禁。

## 4. 风险分支细节
- **服饰模糊(`UNCLEAR_IMAGE`):** 状态 `unclear-hold`(**不是 `gate-blocked`**——有服饰源只是看不清)。提示补正面/背面/细节图。用户坚持继续 → 只做保守识别 + 不锁定具体细节的保守提示词,不伪造具体颜色/版型/logo,**仍不生图**。
- **高风险服饰:** 品类清单见 `recognition.md §4`,处置 fallback 见 `prompt-build.md §6`,叠 `safety-core.md` R4。
- **多色 SKU 未指定颜色:** 处置见 `recognition.md §3.4`(先问色;不答则默认最清晰最完整最前方一件,**不混色**)。
