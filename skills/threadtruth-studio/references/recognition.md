## 2. 服饰事实源规则

上传图是唯一服饰事实源。**必须保留**:颜色、材质、版型、长度、宽松度、领型、袖型、肩线、腰线、下摆、裤脚、裙摆、纽扣、拉链、口袋、图案、logo、文字、鞋、包、配饰。

**禁止:** 重新设计服饰 / 改颜色 / 改材质 / 改长度 / 改版型 / 发明 logo 或文字 / 添加原图没有的外套 / 添加无关配饰 / 混合多个 SKU 颜色。

**配饰稳定:** 原图有鞋/包/项链/手表/戒指/腰带等配饰,必须保持相对关系稳定。优先级:核心服装 > 鞋包 > 大配饰 > 小配饰 > 微小 logo/文字。允许低存在感配饰补齐,但不抢服饰主角,不添加强品牌感配饰。

## 3. 八类输入类型路由

生成前必须先跑输入类型路由,据此设定保真重点与补齐策略:

### 3.1 单件上衣
识别领型/肩线/袖型/袖长/衣长/下摆/门襟/纽扣拉链/文字logo/面料。规则:上衣是主角;自动补齐**低存在感**下装/鞋/极简配饰;至少 2 张图展示完整衣长与下摆,不默认全塞进裤腰;有文字logo启动文字风控;有吊带/bra/露肤启动去性感化。

### 3.2 单件连衣裙 / 长裙 / 袍裙
连衣裙本身即完整造型:不加复杂搭配,不改裙长,不改裙摆层次,不加腰带/外套(除非原图有);中式结构不变古装/戏服/旗袍 cosplay。

### 3.3 完整 outfit
必须保留上装/下装/鞋/包/配饰/色彩关系/穿搭比例/层次/包的佩戴方式/鞋与裤脚裙摆关系。只转译为**所选风格的人像**,**不重新 styling**。

### 3.4 多色 SKU
用户指定颜色按指定;未指定先问;用户要求直接生成且不答 → 默认最清晰/最完整/最前方一件;不混色,不同一模特叠穿多 SKU,批量颜色逐色生成。

### 3.5 文字 / logo
保留 logo/文字的位置、大小、色块关系、视觉节奏;不能准确渲染时保留为正确位置的小图形标记;不发明新品牌/字母/标语;不让文字漂移到背景/裤子/皮肤(对齐 safety-core R5)。

### 3.6 露肤 / 吊带 / bra / 短裙
必须加去性感化(见 `prompt-build.md` 负面词 + `safety-core.md` R4):可保留真实露肤,但不情色化、不廉价性感化;短裙坐姿防走光;禁止卧室/床/暗光/暧昧场景。成人泳装/内衣交平台 moderation 裁决(R4),被拦不绕过。

### 3.7 中式 / 东方结构
保留立领/盘扣/斜襟/袖型/宽松廓形/下摆长度/面料肌理/背部结构线。禁止古装/汉服影楼/旗袍 cosplay/戏服感/扇子/油纸伞/古风道具堆砌。东方结构可保留,整体仍是**现代高端杂志感(对齐所选风格,如新中式 pack)**。

### 3.8 多图事实源
按 role 判断每张图作用并标注 index 喂给 image_gen(见 `prompt-build.md` 参考图规则):
- 正面图→正面结构 / 背面图→背部结构 / 细节图→纽扣刺绣logo领口袖口 / 面料图→材质纹理颜色 / 平铺图→轮廓结构 / 完整搭配图→整体关系
- **冲突优先级:** 清晰主视图 > 局部细节图 > 多数一致信息 > 面料近景 > 模糊图片
- **先分清"同款多视图"还是"多套不同 outfit":** 同一套不同角度 → 本条(合并成一套事实源);多套不同 → 走 §3.9。

### 3.9 多套不同 outfit(B5,防"一次铺开多组并行生 23 张")
- **绝不一次性为所有套并行生成。** 每套都是独立的"一套=一组=6 张闭集"(见 `prompt-build.md §4.0` / SKILL §6 B7 硬上限)。
- **先确认走哪套:** 输出每套简要识别 + 让用户选"先做哪一套",或推荐两段式:**动作 0 出一张六宫格预览(每格=一套 outfit 的代表姿势)**让用户先选方向。
- **逐套串行:** 用户选定某套 → 对**这一套**走完整流程(识别→风格→模式→6 张闭集成片)→ 完成核对→ 再问是否继续下一套。**严禁同时开多套生图、严禁多会话自调度。**
- 不把多套混搭叠穿在同一模特身上,不混色。

### 3.10 输出形态 / Subject output form
默认输出形态是**真人模特服饰人像**。这不是新的常驻菜单;只在识别卡里以"默认 + 可改"的方式露出,避免把前台做成问卷。

可识别/承接的输出形态:
- `真人模特`:默认形态,沿用 `prompt-build.md` 6 姿势母版与头部视线。
- `不露脸局部`:用户说"不露脸/切头/只拍身体/避开脸"时触发;仍可沿用人像姿势母版,但 prompt 必须让脸部离开画面、被自然遮挡或裁到鼻口以下,只保留服饰事实与身体结构。
- `平铺`:用户说"平铺/flat-lay/不要模特/铺拍"时触发;作为非人像输出,不套头部视线与真人姿势母版。
- `挂拍`:用户说"挂拍/衣架/挂着拍/hanger"时触发;作为非人像输出,不套真人姿势母版。
- `人台`:用户说"人台/假人模特/ghost mannequin/mannequin"时触发;无真人脸部身份,突出服饰结构。

安全覆盖:
- 童装敏感品类(尤其儿童泳装/贴身/睡衣/暴露剪裁)默认推荐 `平铺/挂拍/人台`,并在前台明示原因;不得静默把用户预期的"模特图"改成非人像。
- 成人泳装/内衣仍叠 `safety-core.md` R4;输出形态不能绕过 moderation 或去性感化要求。
- 输出形态改变只改变"呈现方式",不放宽服饰保真、风险、授权、tool-blocked、B7 额度上限。

已明确的 `风格 + 模式 + 动作` 不因输出形态未指定而被额外追问;默认 `真人模特`,除非风险规则必须降级或用户主动指定其它形态。

### 3.11 用途交付规格线索
用途/平台线索不仅用于 style-router 权重,也可作为 prompt 与 QA 的**构图默认值**。它不是风格代号,不得覆盖 pack 风格底座。

本文件只负责在识别卡里写短标签/短线索,例如 `电商主图居中留白`、`小红书竖版`、`详情页多景别`、`品牌大片留白`、`无`,并单列已解析的 `目标画布`。**完整用途→比例映射、`canvas_contract` 优先级与声明边界以 `modes-scenes.md §4` 为唯一规则源**,不要在本文件重复维护平台规格表。

目标比例是生成前的批次硬契约,但 prompt 本身不证明原生 host 已遵守;只有落盘元数据通过 `prompt-build.md §4.0b` 才能声明本地文件比例/像素合规。仍不保证平台审核、流量、像素级留白或发布效果。

## 4. 风险等级判断
- **高风险:** 结构极复杂礼服 / 透明材质 / 超短裙 / 大面积复杂图案 / 强民族服饰结构 / 极端前卫设计师款 / 大logo或大段文字 / 多层叠穿结构不清 / **泳装·内衣(叠 safety-core R4)** / **童装敏感品类(叠 R1)**。→ 推荐棚拍版 + 建议先 1 张测试。
- **中风险:** 有文字logo、中式结构、有露肤、单件需验证结构。
- **低风险:** 常规完整 outfit、西装、衬衫、牛仔裤、连衣裙等通勤展示款。
