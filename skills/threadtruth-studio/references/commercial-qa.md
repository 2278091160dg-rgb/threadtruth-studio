# 商业交付 QA 与状态阻断(core,风格无关)

> 本文件定义动作1独立成片的最小商业 QA。它不把 LLM 目测包装成像素测量或平台验收,也不改变 safety-core R1–R7、B7 额度上限或用户付费授权门禁。

## 1. 何时执行

- 每张动作1成片落盘后都执行内部基础 QA。
- 用户出现“商用、上线、客户交付、电商主图、商品详情、投放、品牌大片、可发布、可交付”等意图时,必须输出用户可见的逐张报告 + 整组报告。
- 动作0 contact sheet/preview-grid 不进入商业 QA,也永远不能借 QA 升成片。
- 动作2单张测试可用同一逐张表,但必须标“单张测试,未形成 6 张闭集”。

## 2. QA 处置词(不是新的主生命周期状态)

- `qa-pass`:可见硬事实、适用的身份一致性和构图目标未发现阻断漂移。
- `qa-retry`:发现可见硬事实、身份、人体、安全或交付结构失败;对应图片仍是 `image-draft`,必须重试或移出交付组。
- `qa-user-review`:logo/文字、细微面料、隐蔽结构或源图未提供的角度无法可靠确认;不得自动当作通过,须用户/运营与实物或高清源图比对。

同一张可同时有 `qa-user-review` 项和其它已通过项;只要存在一个 `qa-retry`,整张与整组都不得升 `image-ready`。

## 3. 逐张必查表

先并排对照**当前已锁定 outfit/SKU 的全部上传服饰参考图**;不得只拿 look-1 或上一张生成图互相比,也不得混入未选色或另一套 outfit。

| 维度 | 必查项 | 失败处置 |
|---|---|---|
| 服饰硬事实 | 主色/辅色、可见材质观感、廓形/松量、衣长/裤长/裙长、领口/肩线/袖型/袖长/袖口/下摆 | 可见不一致=`qa-retry`;无法从源图判断=`qa-user-review` |
| 结构件 | 纽扣/拉链/门襟、口袋数量与位置、开衩、腰线、绑带、层叠 | 新增、删除、移位或改造=`qa-retry` |
| 图案与标识 | 图案、logo、字母、标语的位置/大小/方向/是否存在 | 明显漂移=`qa-retry`;小字不可辨=`qa-user-review`,不得声称准确 |
| 原有搭配 | 源图已有鞋、包、腰带、首饰、手表等 | 新增/丢失/换款/换色且用户未授权=`qa-retry` |
| 真人身份 | look-1 后是否保持同一 AI 模特的脸型、发型、表观年龄和身体比例;不露脸是否保持相同轮廓且无可识别脸 | 明显换人或年龄/体型漂移=`qa-retry`;非人像不适用 |
| 人体与安全 | 手指、四肢、关节、遮挡、年龄得体、非性化、R1–R7 | 失败=`qa-retry` 或按 safety-core 阻断 |
| 构图与呈现 | 单图单姿势/单构图、对应编号、服饰为主角、要求保留的下摆/鞋包未裁、无拼图/额外文字 | 失败=`qa-retry` |
| 风格与光影 | 选定 pack 的 visual language、场景和四段光影签名到位,但未改变服饰颜色/材质/结构 | 风格弱可记录优化;一旦改动服饰事实=`qa-retry` |
| 画布元数据 | 实际宽高是否符合 `canvas_contract`;用户未给像素时是否与首张 `batch_canvas_baseline` 完全一致 | 未读元数据、比例失配、显式像素失配或同组尺寸不一=`qa-retry` |
| 用途规格 | 构图、留白、多景别角色是否符合 `modes-scenes.md §4`;目标画布是否已在 prompt 与元数据门禁兑现 | 未达到目标=`qa-retry`;比例通过也不等于平台审核/投放保证 |

动作1/2的工作区文件必须报告实际文件名和图像尺寸。源 checkout 优先运行:

```bash
python3 scripts/image-spec-check.py --ratio <W:H> [--size <WIDTHxHEIGHT>] --same-size <look-1-or-first.png> <new-or-all-look.png...>
```

若工具不在当前安装包,使用 host 的只读元数据能力做等价校验。只有真正读取到元数据才能写“尺寸/比例已核”;无法读取时保持 `image-draft` + `qa-retry`,不能靠目测放行。即使尺寸符合,也不得保证平台审核、流量、留白像素或发布效果。

## 4. 整组必查

动作1准备交付前必须同时满足:

1. 恰好 6 个独立图片文件,编号 look-1…look-6,文件名唯一,无 preview-grid/contact sheet 混入。
2. 真人/不露脸组以已验收 look-1 为身份锚点;look-2…look-6 没有明显换人。非人像组跳过身份项。
3. 六张都以上传服饰图为 source truth,没有跨图累积的纽扣、口袋、袖口、logo、首饰、包型或材质漂移。
4. 六张实际元数据都符合唯一 `canvas_contract`;用户未给精确像素时,六张实际尺寸与首张 `batch_canvas_baseline` 完全一致。preview-grid 不得作为基线。
5. 每张目标姿势/非人像构图编号与裁切要求成立;选定 pack、模式、输出形态和用途线索没有丢失。
6. 所有 `qa-retry` 已用用户明确授权的单张重试关闭;所有 `qa-user-review` 已列给用户核对。
7. B7 调用计数已报告;比例失败不得靠静默拉伸/裁切/加边或自动第 7 次调用掩盖。

## 5. `image-ready` 硬门禁

只有同时满足以下条件才能从 `image-draft` 升 `image-ready`:

- 整组结构检查通过,不存在未关闭的 `qa-retry`。
- 六张的实际比例与像素一致性已用元数据证明符合本组 `canvas_contract`/`batch_canvas_baseline`。
- 用户已对照实物/高清源图确认服饰硬事实可接受,并明确接受或关闭所有 `qa-user-review` 项。
- 用户已知发布时的 AI 生成内容标识义务。
- 任何声明的本地文件像素/比例都有实际元数据证据;平台审核、流量、留白像素与发布效果仍不在保证范围。

AI 自评、历史 evidence README、风格测试板或“Open findings=0”都不能代替本轮用户确认。

```text
- 服饰硬事实: ...
- 结构/logo/配饰: ...
- 身份/人体: ... (非人像写 N/A)
- 构图/风格/光影: ...
- 文件/尺寸: ... / 比例门禁: pass|qa-retry / 批次尺寸门禁: pass|qa-retry

```
