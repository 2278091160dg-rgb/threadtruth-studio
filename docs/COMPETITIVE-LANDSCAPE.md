# Competitive boundary

ThreadTruth Studio sits beside—not above—several useful project categories.

| Category | Typical strength | ThreadTruth boundary |
|---|---|---|
| Product-shot Skills such as [`product-shots`](https://github.com/motiful/product-shots) | Broad product staging and marketing visuals | Apparel portraits only, with garment facts as the authoritative source |
| Virtual try-on systems | Transfer a garment onto a supplied person or body | Does not promise fit simulation or reproduce a supplied person's identity |
| Image API wrappers | Programmatic generation, batching, provider choice | No API key, connector, provider router, or fallback; uses only host-native generation |
| Prompt/style libraries | Fast aesthetic exploration | 24 deterministic packs constrained by source truth, permission gates, and QA |
| Ecommerce asset suites | Many product types and channel formats | Narrower apparel-portrait scope with a six-independent-image closed set |

The differentiators are therefore not “better image generation” claims. They are inspectable workflow controls: source-truth precedence, deterministic route traces, explicit generation consent, identity-only anchoring, a fixed call budget, canvas verification, and evidence-backed commercial QA.

No benchmark in this repository claims superiority over adjacent projects. Comparative claims require a published protocol, rights-cleared inputs, and reproducible results.
