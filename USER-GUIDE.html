它做什么

从一组真实、清晰、可识别的服饰照片开始，输出服饰识别卡、主推与备选风格、完整 24 风格目录，并在用户选择风格和动作后进入后续流程。

01
事实识别
02
确定性路由
03
显式授权
04
六图 QA
  • 六宫格仅用于方向预览，不能当最终成片。
  • 成片是六张独立图片，按 look-1 到 look-6 串行生成。
  • look-1 只锁 AI 模特身份；服饰事实始终来自上传源图。
  • 每张执行服饰、人体、安全、构图、比例和同批尺寸检查。

明确边界

适用于服饰模特、电商人像和时尚编辑类生产。不适用于非服饰商品、纯文字概念图、通用虚拟试衣或 API 集成。

本项目是独立社区项目，不是 OpenAI 官方产品；不保证 CAD/版型精度、真实上身合体效果、logo/小字 100% 准确、平台审核通过、投放效果或无人值守商业交付。

视频、第三方 API、跨平台适配、SaaS 批处理与新增风格包不属于首发范围。

安装与发现

源码仓库为 github.com/2278091160dg-rgb/threadtruth-studio；签名 Beta Release 尚未创建。当前从源码候选仓库测试：在 Codex 的 Plugin source 流程中选择包含 .codex-plugin/plugin.json 的仓库根目录。

  1. 确认根目录 manifest 版本为 1.0.0-beta.1。
  2. 添加本地 Plugin source，并启用 ThreadTruth Studio。
  3. 在新任务中输入 $threadtruth-studio 验证显式发现。
  4. 用“帮我把这件外套做成电商模特图”验证隐式触发；用“给手机做商品图”验证负向隔离。

Beta Release 通过案例与干净安装门后，此处将补充 Release checksum 和已验证的 marketplace 安装步骤。

最快工作流

上传自有且有权使用的真实服饰图
→ “请用 $threadtruth-studio 识别并推荐风格，不要生图”
→ 查看识别卡、主推+2备选和完整24风格目录
→ 选择单一风格代号 + 模式 + 动作
→ 明确授权预览、单张测试或六张成片
→ 对照实物确认服饰事实，关闭 qa-user-review

动作 0 是一张标记为非成片的预览；动作 1 是六张独立成片；动作 2 是一张测试；动作 3 只输出六条提示词且不调用生图。

隐私、权限与成本

  • 运行时不植入遥测。
  • 不需要、不索取、不读取 API key、token、环境变量或历史私有文件。
  • 只读取当前任务中用户主动提供的服饰图，以及本组用于身份锚定和 QA 的输出。
  • 只有明确的生成措辞才授权宿主原生图片生成；六张前会提示额度消耗。
  • 无原生能力时停止，不调用外部 API、CLI、联网脚本或第三方服务。

公开案例必须进入权利清单。客户素材、来源不明图片、带许可疑问的历史证据均不得发布。

如何读状态

状态含义
gate-blocked不是合法服饰事实源或请求越界。
unclear-hold图片太模糊，等待补图或保守处理。
recognition-ready识别和推荐完成，等待选择风格与动作。
style-conflict-hold多个风格冲突，等待确认主次。
prompts-only仅输出提示词，没有生图。
preview-grid方向预览，永远不是最终成片。
image-draft已生成但商业 QA 或人工确认未关闭。
image-ready六张、画布和 QA 全部通过，并经用户核对。
tool-blocked宿主无可用原生生图能力；禁止 fallback。

升级、卸载与回滚

  1. 升级前记录当前 Plugin 版本和测试结果。
  2. 不要同时启用两个具备重叠触发边界的活动 Skill。
  3. 新版失败时先停用新版，再恢复已验证的旧安装；不要删除回滚源。
  4. 卸载后重新打开任务，确认显式调用不再被发现、相邻请求不受影响。

全局旧 Skill 的禁用或归档会改变用户环境，必须另行授权；本地源码构建不会执行这些操作。

常见问题

只上传了图片，为什么没有生图？

上传不等于同意生成。先完成识别和风格选择，再明确选择动作。

为什么不能把六宫格当成片？

预览用于低成本判断方向；裁切预览无法证明六张独立图的身份、画布和服饰 QA。

为什么停在 qa-retry？

服饰硬事实、人体、安全、比例或同批尺寸有阻断问题。单次最多六次调用，额外重试需要新授权。

没有生图工具怎么办？

可继续输出识别卡或六条提示词；切换到支持原生图片生成的宿主任务。不要提供 API key。
